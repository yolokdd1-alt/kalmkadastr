# Подключение заявок к Telegram

Состояние: код подготовлен, подключение к VPS пользователь отложил. Рабочая отправка не включена.

1. В официальном @BotFather выполнить /newbot, сохранить токен вне Git и чатов.
2. Создать закрытую группу, добавить бота и разрешить ему отправлять сообщения и документы. Администратором назначать необязательно, если разрешения группы позволяют отправку.
3. Написать в группе команду /start с обращением к боту. Получить chat.id через getUpdates локальным запросом к Bot API. Не использовать сторонних ботов для передачи токена.
4. На VPS установить Node.js 22+, скопировать server/, создать /etc/kalmkadastr.env по server/env.example с правами 600. Токен хранится только там.
5. Запуск: node --env-file=/etc/kalmkadastr.env /opt/kalmkadastr/server/index.mjs. Для постоянной работы использовать systemd от отдельного непривилегированного пользователя.
6. В Nginx создать отдельный HTTPS-хост для API. Проксировать только /api/enquiries на http://127.0.0.1:8787. Установить client_max_body_size 12m, proxy_read_timeout 120s, proxy_set_header X-Real-IP $remote_addr. Не изменять конфигурацию других сайтов. HTTP порт 8787 наружу не открывать.
7. ALLOWED_ORIGINS должен содержать точный origin сайта без завершающего слеша. В GitHub Settings → Secrets and variables → Actions → Variables задать NEXT_PUBLIC_ENQUIRY_API=https://домен-api/api/enquiries и передать его сборке в workflow. Это публичный адрес, не секрет. Без него формы остаются демонстрационными.
8. До включения приёма заполнить реальные реквизиты и контакты компании, утвердить политику и текст согласия. Нынешняя страница privacy описывает деморежим и не подходит для реального приёма.
9. С разрешения пользователя отправить тестовую заявку с тестовыми данными и файлом. Проверить получение в группе, номер заявки и сообщения об ошибках. Только после этого включать отправку для посетителей.

Тесты: node --test server/telegram.test.mjs. Сетевые запросы в тестах заменены тестовым приёмником. Реальная доставка не проверена.

Ограничения: приём ограничен пятью попытками за 10 минут на IP в памяти процесса. Для нескольких процессов нужен общий лимит на уровне прокси. Текст доставляется раньше файлов; если файл не дошёл, интерфейс сообщает об этом без повторной отправки текста. При сетевом тайм-ауте доставка может быть неоднозначной: автоматические повторы отключены. Постоянной очереди, антивируса вложений и хранения заявок пока нет.
